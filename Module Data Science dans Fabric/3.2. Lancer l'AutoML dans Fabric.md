# 3.2. Lancer l'AutoML dans Fabric

Ce guide explique comment lancer une expérience **AutoML** dans Microsoft Fabric à partir du même fichier source que le reste du module Data Science et pour la même problématique de modélisation : **prédire le nombre de vélos par heure**.

L'objectif est de partir du fichier de comptage vélo, de préparer le dataset de façon cohérente avec les chapitres précédents, puis de laisser Fabric explorer automatiquement plusieurs algorithmes et jeux d'hyperparamètres.

## Prérequis

- Le fichier source **data/comptage-velo-donnees-compteurs.csv** est disponible dans le dossier du module.
- Un notebook Fabric existe déjà pour charger et préparer les données.
- La variable cible est connue : **nb_velos** ou l'équivalent construit à partir du comptage horaire.
- Le workspace **[FORMATION]** dispose des droits nécessaires pour utiliser les fonctionnalités Data Science.
- Copilot est activé dans Fabric pour aider à générer le code de préparation et d'évaluation.

## 1. Reprendre la même base de données

1. Ouvrir le notebook de préparation du dataset.
2. Recharger le fichier source de comptage vélo depuis le Lakehouse.
3. Reproduire exactement la même logique de préparation que dans le notebook précédent.
4. Conserver la même cible métier : **prédire le nombre de vélos par heure**.

Exemple de prompt à donner à Copilot :

```text
Reprends le fichier comptage-velo-donnees-compteurs.csv déjà utilisé dans le module.
Prépare un dataset de modélisation pour prédire le nombre de vélos par heure, avec les mêmes colonnes utiles que dans les chapitres précédents.
```

## 2. Définir le problème AutoML

AutoML va tester automatiquement plusieurs modèles sur la même cible métier.

Dans ce cas d'usage :

- le problème est une **régression** ;
- la cible est **nb_velos** ;
- les variables explicatives reprennent les champs construits à partir du temps et du contexte de comptage ;
- la comparaison des modèles se fait avec une métrique de régression, par exemple **RMSE**.

Exemple de structure attendue pour le dataset :

```python
X = pdf[["station", "jour_semaine", "mois", "heure"]]
y = pdf["nb_velos"]
```

Si ton notebook construit d'autres variables utiles, tu peux les conserver, tant que la cible reste la même.

## 3. Lancer l'expérience AutoML

Dans Fabric, l'expérience AutoML se lance depuis le notebook Data Science en sélectionnant le scénario de machine learning adapté.

1. Ouvrir le notebook de travail.
2. Vérifier que le jeu de données préparé est prêt.
3. Choisir le scénario **régression**.
4. Indiquer la colonne cible **nb_velos**.
5. Lancer la recherche automatique sur les modèles candidats.
6. Laisser AutoML comparer plusieurs approches et conserver la meilleure.

Exemple de prompt à donner à Copilot :

```text
Génère le code ou les cellules nécessaires pour lancer une expérience AutoML dans Fabric.
Le problème est une régression pour prédire nb_velos à partir du dataset préparé à partir du fichier comptage-velo-donnees-compteurs.csv.
```

> **Zone capture d'écran 2** : insérer ici une capture de l'écran Fabric montrant le lancement de l'expérience AutoML.

## 4. Paramétrer la recherche

Pour éviter une recherche trop longue, fixe un cadre simple :

- utiliser un sous-ensemble représentatif si le volume est important ;
- limiter le temps d'exécution de l'expérience ;
- sélectionner une métrique principale claire ;
- garder une colonne cible unique.

Exemple de réglages pédagogiques :

- **Task** : regression
- **Target** : nb_velos
- **Metric** : rmse
- **Time budget** : raisonnable pour un atelier

Exemple de prompt à donner à Copilot :

```text
Ajoute une configuration AutoML simple et pédagogique.
Le problème est une régression, la cible est nb_velos, la métrique principale est RMSE et l'expérience doit rester courte pour un atelier.
```

## 5. Examiner les modèles proposés

Une fois l'expérience terminée, Fabric affiche généralement :

- le meilleur modèle retenu ;
- la meilleure métrique obtenue ;
- l'ordre de priorité des algorithmes testés ;
- les variables les plus influentes si elles sont disponibles.

Points à vérifier :

1. Le modèle correspond bien à une régression.
2. La cible utilisée est bien **nb_velos**.
3. La métrique est cohérente avec le besoin métier.
4. Les résultats sont comparables à ceux des versions précédentes du notebook.

## 6. Comparer avec les autres versions du notebook

Comparer AutoML avec les autres approches du module :

- le premier notebook de base ;
- la V2 avec tuning FLAML ;

- l'expérience AutoML de Fabric.

L'objectif n'est pas seulement d'obtenir la meilleure métrique, mais aussi de garder un pipeline simple à expliquer dans une formation.

Exemple de prompt à donner à Copilot :

```text
Compare les résultats AutoML avec les autres versions du notebook sur la même cible nb_velos.

```

2. Conserver la métrique principale et le type de modèle choisi.
3. Ajouter une courte conclusion dans le notebook.
4. Si besoin, journaliser le résultat dans MLflow pour garder une trace exploitable.

## 8. Bonnes pratiques pour l'atelier

- Garder le même fichier source que les chapitres précédents pour faciliter la comparaison.
- Ne pas changer la définition de la cible entre les versions du notebook.
- Préférer une configuration AutoML courte et lisible pour la démonstration.
- Expliquer que l'intérêt principal d'AutoML est de tester rapidement plusieurs familles de modèles.
- Relire les résultats avant de conclure sur le meilleur modèle.
